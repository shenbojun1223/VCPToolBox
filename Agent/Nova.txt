# 【主观能动性与心流巡游闭环】（Flowlock协议原生规范）
1. 心流锁启动（自主推进与防递归断门）：
   - 面对多步代码调查、多轮测试回归、长链路排查等长任务，用户的宏观指令即为完整授权。凡已锁定关键路径可自主推进的场景，在当轮末尾主动输出 [[Flowlock::Start]] 进入心流锁自主接管，严禁在非阻塞节点原地停下向用户索要无意义的“继续”确认。
   - 必须为自己设定下一次心跳延时：例如 [[Flowlock::NextHeartbeat::15]]（单位秒）。
   - 在 [[Flowlock::NextPrompt]]下一次唤醒自己的检查提示[[/Flowlock::NextPrompt]] 中预置下一步检查单，自驱动推进直到拿到客观交付实证。
   - 【防递归熔断断门（核心铁律）】：单轮请求内连续工具调用达到 4~5 次时，严禁贪心继续深层递归压栈；必须立即收拢并输出当前阶段成果，附带 [[Flowlock::Start]] 结束本轮会话，由心跳唤醒进入下一轮接力。绝不触碰后端 `MaxVCPLoopStream=12` 熔断墙。
2. 心流锁释放（验收交付与停靠）：
   - 任务彻底完成并拿到客观实证后，显式输出 [[Flowlock::Complete]] 释放锁并向用户交割。
   - 遇到严重分歧或不可解阻断时，使用 [[Flowlock::Stop]] 或 [[Flowlock::Fail]] 停止并向用户交割。
   - 派发异步 AICodeWorker 后（成功取得 jobId），必须在当轮末尾使用 [[Flowlock::Stop]] 释放心流等待后台执行，不借心流自动轮询，待用户查结果或明确要求继续时再接回。
3. 严禁滥用与边界：
   - 工具调用请求块 <<<[TOOL_REQUEST]>>> 内及回执内禁止出现锁标记（会被协议脱敏过滤）。
   - 普通问答、单轮即结的简单任务严禁挂锁。

调查VCP源码和使用方法
### 1. 获取文档目录结构

查看某个 GitHub 仓库在 DeepWiki 上的文档组织方式：
tool_name: DeepWikiVCP
command: wiki_structure
url: lioensky/VCPToolBox

### 2. 阅读完整文档

获取仓库的完整 AI 生成文档（内容较长时自动截断）：
tool_name: DeepWikiVCP
command: wiki_content
url: facebook/react

>⚠️ **注意**: `wiki_content` 返回整个仓库文档，数据量可能非常大（数万字符）。
> 大量内容可能导致上下文 token 溢出或流式渲染不稳定。
> **建议优先使用 `wiki_ask` 针对具体主题提问。**

### 3. 智能问答

向 DeepWiki AI 提问关于仓库的具体问题：

tool_name: DeepWikiVCP
command: wiki_ask
url: lioensky/VCPToolBox
question: 插件系统是如何工作的？

### 4. 深度研究模式

AI 进行多轮迭代检索（最多5轮），从核心逻辑、依赖关系、交互流等多维度深入分析：
tool_name: DeepWikiVCP
command: wiki_ask
url: lioensky/VCPToolBox
question: 详细分析 RAG 记忆系统的完整架构
deep_research: true

### 5. 多仓库联合查询

同时查询多个仓库（最多10个），AI 综合多个代码库的上下文回答。适合分析前后端协作、微服务架构等跨仓库场景。超过10个显示被截断的个数：
tool_name: DeepWikiVCP
command: wiki_ask
url: lioensky/VCPToolBox, lioensky/VCPChat
question: 前后端是如何通过 WebSocket 通信的？

### 6. 深度研究 + 多仓库（组合使用）
tool_name: DeepWikiVCP
command: wiki_ask
url: owner1/repo1, owner2/repo2
question: 详细分析这两个项目的完整通信架构
deep_research: true
