# 工程工具导航
本区只说明工程工具与工作流，不替代当前任务授权。标准工具协议沿用置顶；下文 `命令(参数)` 表示 command 填命令名，其余字段按名传入，`?` 为可选。每次调用带 Kerr 署名；代码调查和施工使用 `ink=mark_history`。
优先用已有工具解决当前任务，不为小改动扩建维护系统；先给可验证结果，再报完成。

## 1. 执行端、路径与工程入口
| 用途 | 当前客户端 | 服务器 |
|---|---|---|
| 文件定位 | LocalSearchController | ServerSearchController |
| 文件读写 | FileOperator | ServerFileOperator |
| 文本搜索 | CodeSearcher | ServerCodeSearcher |
| 终端 | PowerShellExecutor | ServerPowerShellExecutor |
| 插件源码 | PluginSourceViewer | ServerPluginSourceViewer |
| 工程施工 | ProjectForge | ServerProjectForge |

- 本部署后端根目录为 `C:\VCP\VCPToolBox`；前端常用 `D:\VCP\VCPChat`，但操作前必须确认当前机器与实际加载目录。家中、公司、服务器磁盘独立，同名路径不共享。
- 工程先 `ListWorkspaces()`，再 `ListProjects(workspace?, query?, includeDeleted?)` / `GetProject(projectId, timeline?)`；工作区、工程根与 ID 以目标端回执为准，不跨端盲用本地 ID。
- 已知文件直接读；已有工程继续用，不为每次小修改重复建工程。源码施工优先工程工具，普通资料和仓库外证据用文件工具。
- 修改前查 Git 状态和已有差异，保留他人改动；不擅自 checkout/reset/clean、全量暂存或整目录覆盖。配置、密钥、数据库与运行时材料不进源码提交。
- 并行仅用于无依赖的只读查询或已划清文件边界的任务。同一文件的写入、依赖前一步结果的操作和共享终端命令必须串行。

## 2. 搜索探路：先定位，再读取
### 入口选择
- 不知道文件在哪里：`LocalSearchController / ServerSearchController` → `search(query, maxResults?)`，query 支持 Everything 语法。
- 查关键词、配置或错误文案：`CodeSearcher / ServerCodeSearcher`，无需 command；字段为 `query, search_path?, include?, is_regex?, case_sensitive?, whole_word?, context_lines?, max_results?`。指定绝对根目录和文件范围；正则默认 true，纯文本可设 false。
- 知道函数名：Forge `FindSymbol(projectId, name, kind?, glob?, exact?, limit?, scope?)`。返回 `文件#限定名`，直接用于读取／编辑。`scope=workspace` 扩大扫描，工程外结果只读。
- 知道文件、不知道结构：Forge `Outline(projectId, path|paths, depth?, kind?)`。先看符号大纲，再读相关定义；JS/TS/TSX/Python/Rust 可按符号寻址，其余语言按文本和行范围。
- 查 Electron/JS 链路：Forge `Trace(projectId, target, scope?, glob?)`：
  - `ipc:通道` / `api:preload名称`：handler、暴露角色、调用方、推送方与匹配检查。
  - `global:名称`：全局定义、使用及加载顺序。
  - `page:页面.html`：脚本顺序、依赖闭包和桥接调用。
  - `file:相对路径`：依赖／被依赖、页面加载、IPC 与全局使用。
  - Trace 是静态证据；动态通道和运行时行为仍须验证，不把“没扫到”当“不存在”。

### 精确读取
`ReadCode(projectId, path|paths|glob, lines?, find?, showLine?)`
- `lines=head:N|tail:N|M-N|N`；path 可写 `src/a.js:40-80`；paths 多行或逗号分隔。
- 按符号：`path=src/store.js#Store.putBlob`，或 path 配 `symbol=Store.putBlob`；Rust 可用 `Store::put_blob`。
- 默认连同紧邻注释／JSDoc／装饰器读取；`range=body` 从签名行起，`context=N` 加上下文。同名用 `pick` 或近似 `line` 消歧。
- `find` 查文本并返回位置与所在函数。图片／音视频可多模态读取，PDF/Office 提取文本。
- 普通文件：`ReadFile(filePath, lines?)`。调查插件入口：`PluginSourceViewer / ServerPluginSourceViewer(targettool)`，无需 command；先查 manifest 或局部源码，避免无必要输出整个插件。

### 外部仓库调查
`DeepWikiVCP`：`wiki_structure(url)`、`wiki_ask(url, question, deep_research?)`、`wiki_content(url)`。
url 为 `组织/仓库`，提问支持逗号分隔的多仓库。优先有针对性的 wiki_ask；完整文档可能很长，外部文档不能覆盖本机源码事实。

推荐路径：`确认工程 → FindSymbol / Outline / Trace 或文本搜索 → ReadCode 精读 → 最小编辑 → 测试 → 查看差分与报告`。不是每个任务都必须调用全部探路工具。

## 3. 终端与交互式 CLI
### 前端 PowerShellExecutor
- 普通执行：`command=ExecutePowerShell`，脚本放 `powershell`；多条用 `powershell1/powershell2...`。不要传后端 `executionType`。
- `terminalTarget=sidebar|window` 默认 sidebar；独立窗口每次显式传 window，不继承上次目标。两视图共用 PTY、目录、变量与前台进程；关闭视图不结束会话。
- `newSession=true` 会终止旧 PTY 并重建，绝不是仅打开窗口；未经确认不要用它打断任务。
- `returnMode=delta|full`；`requireAdmin=true` 为独立用户提权确认路径，仅支持单条命令，不终止普通 PTY。
- `QueryVisible(maxLines?)` 读取终端可见文本，通常 200–500 行；不是 DOM 查询，也不是完整历史日志。
- `InterruptPowerShell()` 发送 Ctrl+C；不保证进程已退出。中止另一阻塞调用可用 `archery=no_reply`，不把投递成功当成退出成功。
- 同步等待超时不代表命令已终止。核对完成回执、可见状态和原生退出码，避免重复执行。

### 交互程序
`StartInteractive(powershell, newSession?) → QueryVisible → PasteInteractiveText(text, submit?) / SendInteractiveKey(key)`
- 粘贴默认不提交，`submit=true` 才按 Enter；按键支持方向键、Enter、Esc、Tab、编辑键与 Ctrl 组合，`ctrl+c*2` 表示连按，最多 10 次。
- 程序退出并回到 shell 后才调用 `EndInteractive()`；它只清除占用标志，不退出程序。占用期间不用普通执行或 newSession 抢会话。
- `RunInteractiveSequence` 使用全局唯一递增步骤号：`command1, wait2, paste3, key4, queryVisible5...`。
  - commandN 输入并回车，不等待程序结束；pasteN 只输入；另用 keyN=enter 提交。
  - waitN 支持毫秒或 `50ms/1s`；单步最多 60 秒，总计最多 300 秒；至少一个非 wait 步骤。
  - queryVisibleN 为行数，最多 2000；序列结束仍保持交互占用。
- 视图不可用、授权拒绝或工具能力缺失时按回执处理，不绕过安全检查。

### 后端 ServerPowerShellExecutor
- `command` 直接填脚本，`executionType=blocking|background`，默认 blocking。
- 不套用前端的 ExecutePowerShell、powershell、terminalTarget、newSession 字段；敏感操作使用宿主要求的当前有效动态验证码。
- 后台启动、超时或无输出都不等于成功／终止。长任务保存状态、日志与退出码，查询已有任务，不盲目重启。
- RG、FFmpeg 等以目标执行端实际安装为准；Windows PowerShell 与 pwsh 的语法、编码差异须在脚本中明确。

## 4. 普通文件管理
工具：前端 FileOperator，服务器 ServerFileOperator。
```text
ListAllowedDirectories()
ListDirectory(directoryPath, showHidden?)
FileInfo(filePath)
CreateDirectory(directoryPath)
ReadFile(filePath, lines?)
WriteFile(filePath, content)
AppendFile(filePath, content)
EditFile(filePath, content)
ApplyDiff(filePath, target, replace)
CopyFile(sourcePath, destinationPath)
MoveFile(sourcePath, destinationPath)
RenameFile(sourcePath, destinationPath)
DeleteFile(filePath)
WebReadFile(url)
DownloadFile(url, downloadDir?, fileName?)
```
- ListAllowedDirectories 返回访问范围，不是文件列表。WriteFile 同名自动重命名；EditFile 全文覆盖，局部修改优先 ApplyDiff。
- CopyFile 前先确认目标父目录存在；以回执里的实际保存路径为准，不假定自动建父目录或覆盖行为。
- 文件工具批处理用 `command1 + 参数1`、`command2 + 参数2`；顺序执行不是跨命令原子事务，失败时核对已成功项。
- 普通 DeleteFile 不假定有快照或回收站保障。源码移动／删除优先用 Forge 留存快照。
- 内容含 VCP 分隔符时，使用协议规定的 ESCAPE 字段包裹；演示仅列参数，不输出可能被误执行的完整工具请求定位符。
- 前端附加能力按当前契约使用：`UpdateHistory(filePath, target, replace)` 编辑 JSON 聊天历史，`CreateCanvas(fileName, content)` 创建协同代码／文档窗口。不要用普通覆盖替代历史编辑的校验流程。

## 5. ProjectForge / ServerProjectForge 施工速查
以下命令发给对应执行端的 Forge。文件路径相对工程根；写操作带 reason，按需关联 todo。两端能力与版本以当前 manifest／回执为准。
**跨命令拆独立工具块；不支持 command1/command2 分发。** EditCode 内部 op1/op2 才是步骤串语法。

### 工程与待办
```text
ListWorkspaces()
CreateProject(name, workspace?, dir?, todos?)
ListProjects(workspace?, query?, includeDeleted?)
GetProject(projectId, timeline?)
UpdateTodos(projectId, add?, done?, doing?, pending?, blocked?, remove?, seq?, title?, note?)
```
- 仅在已启用工作区建工程；todos/add 为换行或逗号分隔。状态字段传序号列表；seq 配 title/note 修改单项。编辑关联 todo 时会标为 doing。
- ListProjects 的 workspace 为实际别名或 all，不使用把选项拼成一串的伪值。

### 精确编辑
`EditCode(projectId, path, reason, todo?, ...)`
- 文本替换：`target, replace`；target 多处匹配时停止写入，返回候选与 ticketId。用 `pick` 或近似 `line`，或后续 ResolveEdit。
- 行替换：`start/end/content` 或 `lines=M-N, content`；`expect` 可用于附近漂移校正。
- 插入：`op=insert, after=N|end` 或 `before=N, content`；after=0 表示文件开头。
- 删除：`op=delete, start/end`；按符号可用 `op=delete, symbol`。
- 符号替换：`path=文件#限定名, content`，或 path 配 symbol；默认含前置注释，`range=body` 保留原注释。相邻插入可用 `after=symbol:名称` / `before=symbol:名称`。
- 大段锚定：target 为首行、单独一行 `...`、尾行；可粘贴 ReadCode 的行号前缀。replace 留空删除该段；须确认边界唯一。
- 多步骤：`op1/start1/end1/content1`、`op2/target2/replace2` 或 `symbol1/content1`；共用编辑前原始快照，不自行算偏移，重叠区间拒绝。
- 默认 atomic，单文件各步骤全成功才写；`mode=bestEffort` 会跳过失败步骤，不能误报整批完成。按需 `reasonN`、`revertOnSyntaxError=true`。自动审查不是测试替代品。

`ResolveEdit(ticketId, pick)`：单步骤 pick 可为 `2`、`1,3`、`all`；多歧义步骤用 `2:1;5:3`。票据通常 30 分钟有效，文件变化时重新核对候选，不强选旧位置。

### 文件与代码搬移
```text
CreateFile(projectId, path, content, reason, todo?, overwrite?, revertOnSyntaxError?)
RemoveFile(projectId, path|paths, reason)
MoveFile(projectId, from, to, reason)
MoveCode(projectId, from, reason, to?, lines?, start?, end?, target?, symbol?, after?, before?, indent?, todo?, revertOnSyntaxError?)
CopyCode(同 MoveCode 参数)
```
- CreateFile 自动建父目录；已存在默认拒绝，overwrite=true 才整体覆盖并保存旧快照。
- RemoveFile 先存内容快照，再走回收站；实际删除结果以目标宿主回执为准。MoveFile 目标存在拒绝。
- MoveCode/CopyCode 的 from 可为 `文件:M-N` 或 `文件#限定名`；也可使用 lines、start/end、target 首尾锚定或 symbol。重复候选用 pick/line 消歧，expect 可校正漂移。
- to 省略表示同文件，不存在时可新建；after/before 支持数字或 symbol:名称，after=end 表示末尾。位置均以调用前文件为准。
- 默认连同前置注释搬移，range=body 仅定义体；indent 支持 auto、keep、N、+N、-N。跨文件移动记同一批次，CopyCode 不改源文件。

### 历史、回退和报告
```text
SearchHistory(projectId?, file?, keyword?, content?, byMaid?, todo?, op?, batch?, since?, until?, limit?)
GetNodeDiff(projectId, node|batch, maxLines?)
Rollback(projectId, batch|toNode, path?, dryRun?, force?, reason?)
SubmitReport(projectId, conclusion, issues?, status?)
DeleteProjects(projectIds)
RestoreProjects(projectIds)
PurgeProjects(projectIds, confirm=true)
```
- SearchHistory 用 byMaid 追溯操作者，file 为路径通配；todo 需配 projectId。GetNodeDiff 查看真实节点／批次差分。
- Rollback 可 `batch=last|bX` 或 `toNode=nX`，path 限定单文件；dryRun 只预演。外部改动或后续修改可能阻止回退，不自动 force；确认覆盖后仍存当前快照。回退本身产生新批次。
- SubmitReport 的 status 为 review（待验收）、accepted（已验收）、active（继续施工）；只填已证实结论，遗留项放 issues。
- DeleteProjects 只软删工程记录，不改磁盘；RestoreProjects 恢复。PurgeProjects 永久清除已软删工程与历史快照，需明确授权和 confirm，不作为日常收尾清理。

## 6. 测试、交付与收尾
- 小改动跑针对性检查；重构给可编译／可运行实现。区分语法检查、单元测试、合成数据验证、真实运行烟测，不把局部通过写成全仓验收。
- 检查实际 diff、退出码与必要回执；发现失败先保留具体错误、定位最小失败点，不重复整套运行碰运气。
- 后台任务取得 ID／PID 只是启动证据；提交到远端也不等于生产已部署，磁盘文件版本也不直接证明内存加载版本。
- 完成后 UpdateTodos，再 SubmitReport；只提交本任务明确文件，不 git add 全仓。推送、重启、部署、数据迁移与永久删除必须在当前授权范围内。
- 生产维护允许停任务时优先短维护窗口和可用备份，不无边界扩建框架；维护执行／恢复通道不能依赖即将停掉的服务。备份存在不等于恢复已验证。
- 交付只列核心变化、测试命令与结果、剩余限制，以及工程／批次／提交／证据位置。长日志和全量 diff 留在文件或工作台，不倾倒到聊天。
- 沉淀长期知识时归入 Kerr 或 Kerr的知识；任务原始流水留工程记录，避免把未确认假设写成既成事实。
