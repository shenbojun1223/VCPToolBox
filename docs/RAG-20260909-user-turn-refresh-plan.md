# RAG 刷新调整：第一项实施计划
日期：2026-09-09
状态（2026-09-10 更新）：配置关闭、PM2 运行环境及保存快照一致性已核验；源码检查与局部隔离回归通过。完整生产行为验收尚未完成，具体边界见文末。

## 目标
真实用户新输入时正常检索注入记忆；同一次请求的工具递归内，不自动重新检索或替换初始 RAG 区块。
模型输出中间结论不触发自动刷新。
保留主动记忆检索工具，其结果作为普通工具回执追加。

## 范围
本阶段只做刷新时机调整。
不做跨轮稳定排序，不做 GravityStub 折叠，不做中间结论分类器，不增加新代理、恢复框架或遥测系统。
用户对中间结论后的检索仍有想法，本轮暂不深入、不扩展实施。

## 最短实施路径
1. 核对现有开关与两个 Handler：
   - 确认 RAGMemoRefresh 只控制工具递归刷新，不影响用户新请求的初始 RAG 处理。
   - 确认流式、非流式都受此开关控制。
   - 简要确认系统心跳等自动续答的实际入口，不把 role=user 直接等同于真实用户新输入；若存在独立入口问题，单列事实，不顺手扩建来源识别框架。
2. 优先只改配置：
   - 现有开关满足目标时，备份 config.env，将 RAGMemoRefresh=true 改为 false。
   - 不改 Handler，不删除既有刷新代码。
   - 只有确认现有开关不足时，才提出最小代码差分。
3. 生效与验收：
   - 已知 server.js 在启动时读取开关；配置落盘与运行生效分开汇报。
   - 所需服务重启另行确认，不自动重启。
   - 优先利用现有测试和下一次自然会话检查三件事：用户新请求仍有初始 RAG；流式和非流式递归不再自动替换 RAG；主动记忆检索仍可使用。
   - 未观察到的路径标为未验证，不为凑验收额外发起模型或 embedding 实验。

## 完成标准
明确记录修改位置、实际配置、生效状态及上述三项检查结果。
不承诺缓存命中率、费用或任务质量必然提升；本阶段不开展新 A/B 实验。
如需回退，恢复原开关并按相同方式加载配置。

## 执行约束
仅备份并修改目标配置项，不覆盖其他工作区改动，不修改 history.json，不提交或推送 Git。
以上为最初实施约束；当前状态以下述核验记录为准。
