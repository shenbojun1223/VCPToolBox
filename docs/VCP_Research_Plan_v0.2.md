## §0 它是什么

**一个短线研究与决策支持系统。**

由专职 Agent 主动发现机会、由确定性代码检验参与规则、由独立审查员挑错，最终输出用户可拍板的条件交易计划，并前向记账反哺规则。

**纪律在这条链上是护栏，不是产品本体。** 这是本版相对初版构想的根本反转，起因是用户明确指出：「我更需要的是 agent 帮我研究什么票值得一试，什么策略胜率高，纪律只是其中的重要一环。」

## §1 主链路

```
① 数据底座        行情 / 公告 / 事件 → 来源、时点、版本可追溯
      ↓
② 专职研究员      主动提出机会研究单（用户不需要先报代码）
      ↓
③ 计算模块        检验「用什么规则参与」
                 扣费后期望 / 回撤 / 分年稳定性 / 分市场状态 / 对照基准
      ↓
④ 独立审查员      时点泄漏 · 无证据断言 · 盈亏比不足 · 暗雷
      ↓
⑤ 用户拍板        → 条件交易计划 → 前向记账 → 回头修正规则
```

## §2 已锁定（不再讨论）

### 2.1 用户画像（本人口述）

- 交易条件：白天交易时段方便看盘操作；资金性质为闲钱。
- 风险陈述：单笔可承受总资金 5% 亏损；总回撤 20% 会难受。
- 战场偏好：历史偏好追科技主线。
- 策略偏好：**先做短线。**
- 四大痛点：不知道买什么、不知道何时买卖、经常被套、亏了舍不得砍。
- 关键自述：「没有什么很成文的交易策略。」

### 2.2 策略范围

**短线。** 研究窗口暂定 1～5 个交易日（研究窗口，非已批准的固定持有期）。

首批三条候选假设：

| 代号 | 规则雏形 | 赚什么 |
|---|---|---|
| A | 突破后首次缩量回踩 MA5/MA10 不破 | 主线趋势延续 |
| B | 板块宽度突破阈值次日买龙头 | 资金扩散初期 |
| D | 缩量横盘 N 日后首根放量阳线破平台 | 变盘方向选择 |

留档不跑：C（科技 ETF 超跌首阳）、E（创新高回调二次新高）——周期属波段，与短线偏好不符。

**砍除依据：A 股短线三项物理约束。**
1. T+1 使隔夜跳空无法用止损规避。
2. 往返成本约 0.15%（佣金双边 + 卖出千一印花）。
3. 涨跌停板导致想买打不进、想卖出不来——回测必须判为未成交。

### 2.3 三源分工（均待验收，为初始定位非永久限制）

| 来源 | 候选定位 | 当前已核验 |
|---|---|---|
| **baostock** | 历史行情候选主源 | 服务器可取 0.9.4；磁盘余 114.8 GB |
| **Kimi Datasource** | 资料 / 财务 / 资讯候选源 | 仅文档评估，未部署未调用 |
| **GuanLan** | 事件观察候选源 | 源码已初查，依赖未装 |
| akshare | 字段补源 | 服务器可取 1.20.24 |

保留 baostock 跑历史库的依据，**不是「MCP 做不到」**（该判断已撤回），而是 Kimi 文档明载两条：数据查询消耗 Kimi Code 套餐额度；不能据来源名称推定批量采集获得授权。拿订阅额度灌一个本有免费合法路径的历史库，是把贵的用在便宜处。

若实测发现 Kimi 能提供缺失字段（尤其 §6 的 R2 行业成员历史），数据路线照改，不为保住既定方案拒绝更好来源。

用户本机未装通达信，本机侧不参与。

### 2.4 组织

新建 **投研研究员** + **投研审查员** 两个专职 Agent：独立实例、独立提示词、独立日记库，**不可合并**（避免自审作业）。

现有三人退出投研判断：Nova 任工程施工，Lucy 任方法论验收，赞妮任流程入口与交付人。

### 2.5 不做

PIT 双时态数据库（30 张表）· research-core 独立服务 · 160 个 E2E · 社媒 NLP 与 2000 条标注 · 自建全量回测平台 · 四容器隔离部署。

## §4 GuanLan 复用裁决

**定位**：V0.1 可选事件发现支路，按命令逐项验收后接入；不作为历史数据与回测的必需依赖。

| 能力 | 处置 |
|---|---|
| 龙虎榜 / 大宗 / 解禁 / 业绩预告 | **优先评估复用**（研究员找线索的实际价值） |
| 行情 / 基本资料 / 技术指标 | 验收口径后复用；指标须独立样本对照 |
| ATR 跟踪止损逻辑 | 可提取为纯计算模块，补边界测试。算得对 ≠ 该退出规则赚钱 |
| **费率公式** | **不得直接抄为权威口径**（硬编码印花税、按代码前缀判收费，须按交易日期与用户实际券商费率重核） |
| **静态行业字典** | 仅可辅助名称规范化，**不能代替历史行业成员关系** |
| 温度计评分 / 选股框架 / 内置回测 | 不用于证明策略有效（内置回测含未来函数，硬否决）；其中规则可登记为研究假设 |
| 账户 / 持仓 / 交易写操作 | 不接入真实账户记录链路 |

**已确认的源码缺陷**（`Plugin/GuanLan/main.py`）
- `market_temperature()`（1117 行起）：涨跌停数先置零，接口异常被 `except: pass` 吞掉，成交额缺列按零计算 → 取数失败可被误读为真实市场状态。
- `sector_rotation()`（989 行起）：依赖明文 `http://api.tushare.pro`（213 行）；无 Token 时降级为 `snapshot_only`，算不出 5/10/20 日动量。
- `kline_indicators()`（1876 行）：主源新浪不复权，降级 AKShare 为 `qfq` 前复权 → 静默切换复权口径。
- `backtest()`：信号当日按收盘价成交 → 未来函数。

**受限适配层四项职责**（不必一开始做成大服务）
1. 只开放验收过的命令与参数，不把通用 `action` 接口交给研究员。
2. 保留实际来源、取得时间、原始响应、错误状态；**空结果与请求失败分开**。
3. 验证查询路径无未批准写入或凭据暴露（不凭命令名字判断「纯只读」）。
4. 当前查询结果不得冒充历史数据；未核线索不得变成公司事实。

直接调 AKShare 同样需要以上四项。**比较标准是维护与验收总成本，而非「少一层包装必然更好」。**

环节 1 另需一份**复用评估表**：命令用途 / 实际来源 / 时间与字段 / 是否写状态 / 失败行为 / 验证结果。先覆盖解禁、业绩预告、龙虎榜，不扩成全插件翻修。

## §5 Kimi Datasource 四层验收（环节 6）

| 验收层 | 要证明什么 |
|---|---|
| **连接与权益** | 当前受支持的接入方式、账号权限、额度与数据保存用途；旧适配器（v3.4.0 固定 commit）是否仍适用 |
| **实际取数** | 读取当前接口说明后，完成少量与 A 股相关的财务／资讯查询，完整结果可读 |
| **投研价值** | 针对一个候选公司或行业，能否提供有出处、有时间、可与原始披露核对的有效材料 |
| **接入成本** | 延迟、额度消耗、缺失字段、错误处理，以及需要补多少适配代码 |

**追加约束：世界银行查询成功只证明那条链路，不替代 A 股数据权限验收。**

### 事实校准（三条，防下一环节踩）

1. `C:\VCP\CLIProxyAPI` 目录存在 **仅证明目录存在**，不证明进程在跑、凭据有效或数据权限通过。
2. **「8038」在两份文档中解释冲突**：一份称监听端口，另一份明确写「不要把这串数字直接当成端口」，按 v8.0.38 版本核实。实施时必须查实际部署，不得任选一种当事实。
3. **「几十行包装即可接通」是设计可行，不是验收结论。** 进程生命周期、请求对应、超时、业务错误、文件落地、凭据隔离均须处理——这正是第四层「接入成本」要量出来的东西。

### 值得单独留存的工程模式

runbook 的核心设计：**MCP 不复制 token，每次调用重读 CPA 原始凭据文件，刷新仍由 CPA 负责。** 这是干净的「单一凭据真值源」，与本方案「不建第二个账本真值源」是同一原则的不同应用。**该模式本身值得留存，与是否接 Kimi 无关。**

## §6 红线与风险

### 八条红线（违反即停，不是偏好）

1. 任何形式的未来函数（含信号日收盘成交、用今天的成分/数据回填历史）。
2. 数据源静默切换（复权口径、主源降级）不告警。
3. 取数失败按零值继续计算。
4. 关键数字由 LLM 口算而非脚本产出。
5. 未核传闻写入事实区；多个转载充当独立来源。
6. 示意/演示数字不标注 `[示意·非真实]`；**「文档未提及」不得写成「不提供」**。
7. 模拟净值外推为真实可实现收益。
8. 未经用户确认写入真实账户记录链路。

### 六项已知风险

| # | 风险 |
|---|---|
| R1 | **短线是费用最敏感的战场。** 往返约 0.15%，T+1 使跳空无法止损规避，且有大量程序化资金做同样的事。**预期 A/B/D 扣费后期望大概率接近零或为负**——那同样是有价值的结论，但不是用户想要的那个 |
| R2 | **行业成员关系可能无法历史重建。** 若成立，规则 B 的历史验证须降级或暂缓，不得用今天的板块成分回填过去。这是环节 1 的单独结论项 |
| R3 | **akshare 无版本保证**，会限流、会改字段。补源字段压在它身上，属已知最脆环节 |
| R4 | **专职 Agent 隔离靠约定不靠机制。** 提示词写「只读」不是权限控制。第一期不包装这一点 |
| R5 | **跨话题单聊产生上下文碎片。** 对策是自包含交接单 + 本文件为唯一基准。**某环节改口径未回写，主线即失真** |
| R6 | **Kimi 侧三项未知**：VCP 能否承载该工具链路；官方 2026-11-03 刚迁移插件市场（我们接的是已不在主干的历史版本）；额度与数据保存用途边界 |

## §8 承诺边界

**承诺**：给出的每个数字都是算出来的而非说出来的；每条结论可追到数据、代码与时点；失败的试验同样留档。

**不承诺**：找到正期望策略 · 提高胜率 · 预测方向 · 任何形式的收益。

v0.2 通过的是**研究工程启动**，不代表策略已有效，也不代表共享环境已获准随意修改。**每个环节的实际改动，仍需用户在对应单聊中单独授权。**

## 交接单 A｜环节 1 · 数据底座（对接 Nova）

**背景**：为 VCP 投研系统 v0.2 建立短线研究的历史行情底座。主人是 A 股短线交易者（1～5 日），偏好科技主线。本环节不做全市场下载，只做链路验收。

**已锁定的约束**
- 候选主源 baostock（服务器可取 0.9.4），akshare 作字段补源（1.20.24）。
- 落地：服务器本地 Parquet + SQLite 索引。计算全部由 Python 确定性脚本完成，**不经过 LLM**。
- 主人本机未装通达信，不考虑本地 vipdoc 路线。

**目标交付物（三件）**
1. **小样本冻结数据包**：少量标的 × 足够长区间，含完整字段。
2. **字段与覆盖报告**：逐字段说明实际取到什么、单位、复权口径、缺失情况。
3. **缺口清单**：哪些必需字段取不到、替代方案与代价。

**必需字段（少一个都跑不了回测）**
① 日线 OHLCV ② 复权口径（明确是什么，不是「有」） ③ 停牌标志 ④ 涨跌停价（或可按板块规则推算） ⑤ 换手率 / 流通市值 ⑥ 行业归属

**必须单独出结论的一项**
**行业成员关系能否历史重建？**（即「2023 年某日该股属于哪个行业」）这是风险项 R2。若不能，规则 B 的历史验证须降级或暂缓——**不得用今天的成分回填过去**。

**禁区**
- 不得在小样本未通过前扩量下载。
- 不得静默切换数据源或复权口径；切换必须告警。
- 取数失败不得按零值继续，必须显式报错或标记。
- 不得使用 GuanLan 的内置回测、选股、温度计评分。
- 不得启用 Tushare Token（明文 HTTP 问题未修）。

**附加任务**：GuanLan 复用评估表（命令用途 / 实际来源 / 时间与字段 / 是否写状态 / 失败行为 / 验证结果），先覆盖解禁、业绩预告、龙虎榜三项。

**交付标准**：同一份数据重复生成三次，哈希一致。报告中每个结论可指向具体接口返回或源码行号。

## 交接单 B｜环节 2 · 规则定义与试验登记（对接 Lucy）

**背景**：同上。本环节把三条模糊的短线模式写成无歧义的可计算条件，并在跑数据前完成试验登记。

**目标交付物（四件）**
1. **A/B/D 规则定义书**
2. **数据需求清单**（与交接单 A 的字段对齐）
3. **市场状态划分口径**（确定性规则，用于分象限出成绩）
4. **试验登记表**（先注册后跑）

**三条待定义规则**
- **A**｜突破后首次缩量回踩 MA5/MA10 不破
- **B**｜板块宽度突破阈值次日买龙头
